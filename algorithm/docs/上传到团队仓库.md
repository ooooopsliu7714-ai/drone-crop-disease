# 上传到团队仓库指引（算法侧）

目标仓库：`ooooopsliu7714-ai/drone-crop-disease` → 你的目录是 **`算法/`**（目前只有 `.gitkeep`）。

## 一、核心原则：代码进仓库，模型进 Releases

不能把开发目录整个传上去。实测体积：

| 内容 | 体积 | 能否进 git | 原因 |
|---|---:|---|---|
| 代码 + 配置 + 测试 + 脚本 | **0.86 MB** | ✅ 进 | |
| 文档 | 0.09 MB | ✅ 进 | |
| PPT | 2 MB | ✅ 进 | |
| 模型 sidecar（`model.onnx.json`） | ~3 KB | ✅ 进 | 描述模型契约，属于代码 |
| `.pt` 权重 | 554 MB | ❌ | 每文件 78~84 MB |
| **ONNX 模型** | 315 MB | ❌ | 单文件 77/84 MB |
| 交付包 zip | 165 MB | ❌ | |
| `data/` 数据集 | 144 MB | ❌ | 仓库已有「数据」目录 |
| `.venv/` | **7544 MB** | ❌ | 绝对不行 |

**GitHub 的硬限制**：

- 单文件 > **100 MB** → 推送直接被拒
- **网页界面**上传 → 单文件 **25 MB** 上限
- 仓库长期 > 1 GB → 会被警告

> ONNX 文件虽然卡在 100 MB 以下，但**仓库会永久膨胀**，每次 clone 都要拉 165 MB。
> 而且网页上传根本传不了（25 MB 限制）。所以走 Releases。

## 三、两种上传方式

### 方式 1：git 命令行（推荐，一次到位）

```bash
# 1) 克隆仓库
git clone https://github.com/ooooopsliu7714-ai/drone-crop-disease.git
cd drone-crop-disease

# 2) 把解压出来的内容放进 算法/ 目录
#    （.gitignore 也放进去）

# 3) 确认没有大文件混进来
git status --short
du -sh 算法/            # 应在 1~2 MB 左右

# 4) 提交并推送
git add 算法/
git commit -m "算法：RT-DETRv2 检测 + DINOv2 分类 + FastAPI 接口（含测试与文档）"
git push origin main
```

**推送前务必检查**：`git status` 里不应出现 `.onnx` / `.pt` / `.venv`。

### 方式 2：网页上传

仓库页 → 进入 `算法/` → `添加文件` → `上传文件` → 把解压后的**文件夹整体拖进去**。

⚠️ 网页上传**不支持空目录**，`src/` 这类深层目录建议用方式 1。

仓库 → 右侧 `发行作品` → `创建新版本` → Tag 填 `v0.1.0-models` →
把这两个文件作为附件上传：

```

```

Releases 附件**单文件上限 2 GB**，且不占仓库体积，还能版本化。

**方案 B：直接发交付包**

`drone-crop-disease-algo_交付包.zip`（164.6 MB）里已含模型 + 代码 + 示例图 +
脱敏 `.env`，解压即可自测。走微信/网盘更省事。

> 两种方案不冲突：**Releases 给"要跑服务的人"，交付包给"要完整自测的人"。**

