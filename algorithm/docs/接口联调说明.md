# 算法侧接口联调说明

> 本文档中的请求/响应样例**由真实运行的服务抓取**（`runs/api_examples.json`），
> 不是手写示例。重新生成：`python scripts/make_api_handover.py`。
> 抓取时间与服务状态见文末。

## 一、算法侧交付边界

| 项 | 归属 |
|---|---|
| `POST /algo/predict` 及其字段语义 | **算法侧负责**（已完成并 HTTP 实测） |
| `GET /health`、`GET /algo/labels`、`GET /algo/result/{image_id}` | 算法侧附带提供 |
| Apifox 文档、小程序页面、用户体系 | 后端/前端负责 |
| 图片存储与 `image_id` 分发 | **需与后端确认**（见第四节问题 2） |

## 三、两种调用方式与真实响应

### 方式 A：JSON + `image_id`（Apifox 定义的形态）

```bash
curl -X POST http://127.0.0.1:8000/algo/predict \
  -H "Content-Type: application/json" \
  -d '{"image_id": "Image_004_jpg.rf.7f932c1e922cca5585ba276c8371d128.jpg"}'
```

**HTTP 200**，响应（截断）：

```json
{
  "code": 200,
  "message": "success",
  "image_id": "Image_004_jpg.rf.7f932c1e922cca5585ba276c8371d128.jpg",
  "disease_name": "stressed",
  "disease_name_cn": "受胁迫",
  "confidence": 0.1705,
  "severity": "severe"
}
```

关键字段：

| 字段 | 类型 | 示例值 | 说明 |
|---|---|---|---|
| `code` | int | `200` | 200 表示成功 |
| `message` | string | `'success'` | 固定 `success` |
| `disease_name` | string | `'stressed'` | **英文标识**，前端做映射用这个 |
| `disease_name_cn` | string | `'受胁迫'` | 中文展示名 |
| `confidence` | number | `0.1705` | 主病害置信度 |
| `severity` | string | `'severe'` | `healthy` / `light` / `moderate` / `severe` |
| `boxes` | array | 共 12 个 | 见下 |
| `processing_time` | number | `0.0804` | 秒 |
| `model_version` | string | `'det_rtdetrv2:rtdetrv2'` | 便于定位线上是哪个模型 |
| `backend` | string | `'onnxruntime'` | 实际生效的后端 |
| `within_latency_budget` | bool | `True` | 是否在延迟预算内 |

`boxes[]` 单个元素（**同时给了归一化与像素两套坐标**，前端按需取）：

```json
{
  "disease_name": "stressed",
  "disease_name_cn": "受胁迫",
  "confidence": 0.1705,
  "severity": "severe",
  "class_id": 1,
  "x": 0.598709,
  "y": 0.430807,
  "w": 0.399842,
  "h": 0.568063,
  "x1": 383.17,
  "y1": 275.72,
  "x2": 639.07,
  "y2": 639.28,
  "label": "stressed",
  "score": 0.1705,
  "bbox": [
    383.17,
    275.72,
    639.07,
    639.28
  ]
}
```

- `x, y, w, h`：**归一化**（0~1），相对图片宽高 → 适合前端按容器比例画框
- `x1, y1, x2, y2`：**像素**坐标 → 适合后端裁剪/存档
- 兼容别名：`label` / `score` / `bbox`

`statistics`：

```json
{
  "total_boxes": 12,
  "diseased_ratio": 1.0,
  "disease_index": 152.927,
  "severity_ratio": {
    "healthy": 0.785325,
    "severe": 1.52927
  },
  "class_ratio": {
    "healthy": 0.785325,
    "stressed": 1.52927
  }
}
```

`advice`：


### 方式 B：multipart 上传文件

```bash
curl -X POST http://127.0.0.1:8000/algo/predict -F "file=@test.jpg"
```

**HTTP 200**，响应结构与方式 A 完全一致。

### 错误路径

缺 `image_id` 时返回 **HTTP 422**（FastAPI 校验错误），
**不会返回 5xx**：

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": [
        "body",
        "image_id"
      ],
      "msg": "Field required",
      "input": {
        "no_image_id": 1
      }
    }
  ]
}
```

算法侧的降级链为 `ONNX → PyTorch → 规则基线`，任一级失败都会**降级并回报原因**，
接口始终返回可用结构而不是抛 500。

## 四、需要与后端确认的 4 个问题

### 问题 1（最重要）：`disease_name` 的取值集合约定

当前模型是**二分类**：`healthy, stressed`。

如果 Apifox 里 `disease_name` 的枚举是按**具体病种**（如 `rice_blast`）设计的，
则需要：
- **方案 1**：数据集扩到病种级标注（工作量大，需重新标注）
- **方案 2**：Apifox 增加一个"胁迫状态"枚举值，前端按二分类展示（**建议**）

**请确认 Apifox 中的枚举定义。**

### 问题 2：`image_id` 对应的图片存在哪里

方式 A（JSON）**从服务端 `data/uploads/` 目录读图**，所以调用前图片必须已在服务端。
需要确认：

- 是小程序先上传（走方式 B），再由后端把图片落到 `data/uploads/` 并返回 `image_id`？
- 还是无人机/后端已经存好图，算法服务直接挂载该目录？

**当前约定**：算法服务读 `data/uploads/`，支持子目录递归按文件名匹配
（例如放在 `data/uploads/stress2_test/` 下也能找到）。

### 问题 3：延迟预算与部署形态

实测延迟（ONNX CPU）：**冷路径中位 65 ms**（推理+解码+NMS），
缓存命中约 1 ms。响应里的 `within_latency_budget` 会标注是否超预算。

请确认：
- 部署在哪台机器（是否有 GPU）？
- 预算上限是多少毫秒？
- 是否要求批量接口？

### 问题 4：`severity` 的分级口径

当前按**病斑面积占整图比例**分档：`<2%` 轻度、`2%~10%` 中度、`>10%` 重度
（阈值在 `configs/labels.yaml`，可调）。

**注意**：本数据集的标注框互相重叠，框面积之和会超过整图，因此
「发病率 / 病情指数」在该数据集上不可用（服务会自动加 `area_metric_note` 说明）。
若后端需要严格口径，请确认是否改用框面积并集。
