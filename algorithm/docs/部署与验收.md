# 部署与验收（最短路径）

> 这份文档只讲**把算法服务跑起来**。训练、调参、数据集制作请看 `REQUIREMENTS.md`
> 与 `docs/`（那些文档含大量 GPU 训练内容，部署阶段不需要）。

## 一、你需要什么

| 项 | 要求 | 说明 |
|---|---|---|
| Python | **≥ 3.10** | 开发环境用的是 3.10 |
| 磁盘 | ≥ 1 GB | 模型约 161 MB + 依赖约 500 MB |
| GPU | **不需要** | 默认走 ONNX CPU 后端，实测冷路径中位 65 ms |
| 网络 | 不需要 | 模型已随包提供，不联网 |

## 二、安装（两条命令）

```bash
# 1) 建虚拟环境（可选但推荐）
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

# 2) 安装依赖（pyproject.toml 已声明，onnx 是部署必需的 extras）
pip install -e ".[onnx]"
```

> ⚠️ **`.[onnx]` 这个后缀不能省**。核心依赖里没有 `onnxruntime`，
> 少了它服务会退化成 PyTorch 后端（需再装 2.5 GB 的 torch）
> 或最终回退到规则基线，结果会明显变差。

安装后自检：

```bash
python -c "import onnxruntime, fastapi, uvicorn, cv2, yaml; print('依赖 OK')"
```

## 三、验收（一条命令）

```bash
python scripts/smoke_http.py --port 8077
```

它会自动：启动真实 uvicorn → 测 `/health` → 用 JSON 与 multipart 各调一次
`/algo/predict` → 测错误路径 → 测延迟。包内 `data/uploads/` 已放好 3 张示例图。

**期望输出**（本机实测）：

```
[PASS] /health 就绪：backend=onnxruntime
[PASS] JSON  image_id=Image_001...  HTTP 200  healthy  conf=0.1493 框数=4
[PASS] JSON  image_id=Image_004...  HTTP 200  stressed conf=0.1705 框数=12
[PASS] multipart Image_001...       HTTP 200  healthy 框数=4
[PASS] 缺字段 -> HTTP 422（应 4xx，不能 5xx）
✓ 真实 HTTP 冒烟通过
```

## 四、启动服务

```bash
python -m uvicorn src.api.app:app --host 0.0.0.0 --port 8000
```

再跑一遍回归测试确认代码完整（29 项，约 1 分钟）：

```bash
python tests/run_all.py
```

## 五、⚠️ 一个必须知道的坑：标签体系

**正确输出**：`disease_name = "stressed"` / `disease_name_cn = "受胁迫"`

**如果看到 `rice_blast` / `稻瘟病`，说明包根的 `.env` 丢了或没生效。**

原因：本模型是 **2 类**（healthy / stressed），而仓库里还有一套 **15 类病害表**
（`configs/labels.yaml`）。不指定 `ALGO_LABELS_FILE` 时会回退到 15 类表，
于是 class_id=1 被解释成"稻瘟病"。

**关键点：这种错误不会报错** —— HTTP 200、字段齐全、框也画得出来，只是病名是错的。

包内 `.env` 已配好：`ALGO_LABELS_FILE=configs/labels_stress2.yaml`
（相对路径，与当前工作目录无关，从仓库任意位置启动都生效）。

## 六、可选：调阈值

模型分数整体偏低，sidecar 里已按 val 集标定为 **0.10**（F1 最佳）。如需调整：

| 场景 | 设置 | 效果（val 集实测） |
|---|---|---|
| 早筛，宁多报不漏报 | `ALGO_CONF_THRESHOLD=0.05` | 召回 **0.81**，误报较多 |
| 默认 | 不设（用 sidecar 的 0.10） | P 0.386 / R 0.473 / F1 0.425 |
| 高精度复核 | `ALGO_CONF_THRESHOLD=0.15` | 精确率 0.521，召回降到 0.163 |

## 七、出问题时的排查顺序

1. `python scripts/smoke_http.py` 的输出 —— 它会直接指出哪一步失败
2. `runs/http_smoke_server.log` —— uvicorn 的启动日志（端口占用、模型加载失败都在这）
3. `GET /health` —— 看 `backend` 字段是不是 `onnxruntime`；若是别的，说明 ONNX 没装好
4. 病名不对 → 看第五节
